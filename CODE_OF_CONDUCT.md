# Code of Conduct

This project is small and the people in it are reachable. The short
version:

## Expected behaviour

- Be accurate. If a result does not reproduce, say so — in the issue,
  in the pull request, and in the document. A wrong number that nobody
  checked is worse than a null result.
- Be respectful in issues, pull requests and reviews. Assume the other
  person checked their own work carefully.
- Credit other people's work, including the upstream projects whose
  data and code this repository builds on (FinaleDB, the
  cfdna-fragmentomics-pipeline, GDC, GEO).

## Unacceptable behaviour

- Harassment, personal attacks, or sustained disruption of discussion.
- Publishing anyone's personal or patient-identifiable data, or
  attempting to de-anonymise a cohort. This project's data is public
  and IRB-free by design; keep it that way.
- Presenting a simulation result as a clinical one, or presenting a
  single-run number as a stable benchmark.

## Scope

This applies to the repository's issues, pull requests, discussions and
any other space where someone is representing the project. It also
applies to the contributions themselves: code and data that violate
these expectations will not be merged.

## Reporting

Open an issue on the repository, or contact the maintainer through
their GitHub profile or the ORCID record in `AUTHORS`. Reports are
handled by the maintainer; if a report involves the maintainer, it
goes to the reviewers named in `TEAM.md` §4.1.

The maintainer is expected to acknowledge a report, keep the reporter's
identity confidential, and to take a view on what happened before any
change is made to the project.
